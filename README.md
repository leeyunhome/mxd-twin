# mxd-twin

복합단지(오피스) 공간을 3D Gaussian Splatting으로 재구성하고, 그 위에 **서로 다른 통신 규격의
설비 계통을 하나의 관제 화면으로 통합**한 프로토타입입니다.

데모: https://leeyunhome.github.io/mxd-twin/

---

## 무엇을 보여주는 프로젝트인가

빌딩 관제에서 어려운 부분은 개별 시스템을 붙이는 것보다 **이미 규격이 제각각인 시스템들을 하나의
운영 화면으로 모으는 일**입니다. 이 프로토타입은 그 지점만 집중해서 보여줍니다.

1. **이종 규격 → 단일 정규화 스키마** — 계통마다 수집 규격이 다르지만(Modbus TCP, BACnet/IP,
   RTSP, MQTT, OCPP, 접점) 관제 화면에서는 동일한 상태 모델(정상/주의/경보)로 다룹니다.
2. **표가 아니라 공간에서 식별** — 경보가 뜨면 목록에서 행을 찾는 대신 카메라가 해당 위치로
   이동합니다. 어느 구역인지가 바로 보입니다.
3. **경보에 대응 절차(SOP)를 붙임** — 경보를 띄우는 데서 끝내지 않고, 시설팀이 그 자리에서 따라갈
   수 있는 순서·판단 기준·에스컬레이션 기준을 같은 패널에 묶었습니다.

## 규격 표기 — 실무 / 사양 구분

화면의 계통 목록에는 규격마다 배지가 붙습니다. **직접 다뤄본 규격과 인터페이스만 정의한 규격을
섞지 않기 위한 표시**입니다.

| 계통 | 수집 규격 | 구분 | 근거 |
| --- | --- | --- | --- |
| 공조 | Modbus TCP | 실무 | Node-RED 통합관제에서 Modbus Holding Register 수집 |
| 전력·에너지 | Modbus TCP | 실무 | Modbus 계측값 수집·대시보드 시각화 |
| 출입·보안 | RTSP + 접점(DI) | 실무 | RTSP 스트리밍 통합관제 화면 자체 개발 |
| 소방·누수 | 접점(DI) | 실무 | 화재감지 연동 통합관제 화면 개발 |
| 조명 | BACnet/IP | 사양 | 어댑터 인터페이스만 정의 |
| 재실 | MQTT | 사양 | 어댑터 인터페이스만 정의 |
| EV 충전 | OCPP 1.6J | 사양 | 어댑터 인터페이스만 정의 |
| 디지털 사이니지 | HTTP API | 사양 | 어댑터 인터페이스만 정의 |

## 공간 모델

- 원본 3D 모델: [Minimalistic Modern Office](https://sketchfab.com/3d-models/minimalistic-modern-office-5540183da1c7452f810f8de33734879a)
  by [dylanheyes](https://sketchfab.com/dylanheyes), CC-BY-4.0.
- **실측 스캔이 아닙니다.** 공개 3D 모델을 카메라 포즈를 직접 지정해 렌더(고도각 8~65°, 방위각 360°,
  200장)한 뒤 3D Gaussian Splatting으로 재구성했습니다. 포즈를 아는 상태로 렌더하므로 COLMAP이
  필요 없습니다.
- held-out 시점 PSNR 23.1dB / SSIM 0.918.
- 유리·바닥 반사처럼 시점에 따라 달라지는 재질은 재구성이 어려워 **일부 각도에서 반사 스트릭이
  남아 있습니다.** 스케일·불투명도 기준 프루닝으로는 해결되지 않아(부유물이 아니라 시점 의존
  아티팩트) 현재는 학습 커버리지 범위로 시점을 제한해 사용합니다.
- 파일이 319MB라 GitHub 100MB 제한을 넘어 Hugging Face Hub(public)에 두고 불러옵니다.

## 센서 좌표를 정한 방법

`building-twin`(교실)에서는 Blender 씬의 개별 오브젝트(`ceilingLamp`, `radiateur` …) 월드좌표를
그대로 앵커로 썼습니다. 이 오피스 모델은 오브젝트가 아니라 **재질별로 병합된 메시**(Glass /
Structure / Table / Chair / Plants / Lights / Carpet)라 같은 방식이 성립하지 않았습니다.

그래서 **학습된 splat 포인트클라우드 자체를 축별로 투영해** 바닥·천장·유리 파사드·화분·테이블의
실제 위치를 좌표로 읽어낸 뒤, 그 구조 위에 센서를 배치했습니다. 임의 좌표에 흩뿌린 것이 아니라
재구성된 공간에서 확인되는 구조물에 맞춰 놓은 것입니다. 생성 로직은
[tools/make_sensor_layout.py](tools/make_sensor_layout.py)에 있습니다.

## 센서 값

**실제 설비와 연동하지 않습니다.** 값은 `src/sim.js`에서 생성합니다. 계통별 정상대역 안에서 완만한
랜덤워크를 돌리다가 주기적으로 하나를 이상 상태로 밀어, "이상 발생 → 공간에서 위치 식별 → 대응
절차 확인"까지의 동선을 재현합니다.

## 구조

```
index.html
src/
  app.js     # 3D 무대·마커·카메라 이동·SOP 패널
  sim.js     # 계통별 값 시뮬레이션
  style.css
data/
  sensors.json   # 8계통 19센서 (tools/make_sensor_layout.py 산출물)
  sop.json       # 계통별 경보 대응 절차
tools/
  make_sensor_layout.py
```
