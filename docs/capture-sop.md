# 실제 부지 3DGS 촬영·구축 SOP

> 이 데모(mxd-twin)는 공개 3D 모델을 렌더해 학습한 것입니다. 실제 건물에 적용할 때
> 무엇을 어떤 순서로 해야 하는지를 이 문서에 정리합니다.
> 촬영 → 학습 → 센서 배치 → 관제 연동까지, 현장 인력이 그대로 따라갈 수 있는 수준을 목표로 합니다.

---

## 0. 적용 시점 — 준공 전에 정해야 하는 것

3DGS 트윈은 **준공 후에 찍는 것**이지만, 준공 후에 찍을 수 있으려면 **설계·사양 단계에서
미리 요구해 둬야 하는 것**이 있습니다. 이 문서의 §5가 그 목록입니다.

| 단계 | 이 문서에서 할 일 |
|---|---|
| 설계·사양 확정 | §5 — 발주 사양서에 넣을 요구사항 (센서 좌표 메타데이터 포맷, 프로토콜, 납품물) |
| 시공 중 | §4 — 은폐되기 전에 찍어야 하는 것(천장 속 배관·덕트) |
| 준공 직후 | §1~3 — 본 촬영 |
| 운영 | 변경 발생 구간만 재촬영(부분 갱신) |

## 1. 외관 촬영 (드론)

| 항목 | 기준 |
|---|---|
| 고도 | 3개 고도 (저/중/고) × 각 고도마다 오비탈 1바퀴 |
| 짐벌 각 | 5° / 25° / 45° — 고도별로 다르게 |
| 오버랩 | 인접 프레임 **80% 이상** |
| 매수 | 1,500~3,000장 (건물 규모에 비례) |
| 시간대 | 흐린 날 우선. 맑은 날이면 정오(그림자 최단) 회피하고 오전/오후 |
| 금지 | 자동 노출·자동 화이트밸런스 (프레임마다 밝기가 바뀌면 학습이 무너짐) |

**유리 커튼월 주의**
반사면은 3DGS의 대표적 난제입니다. 시점마다 비치는 내용이 달라져 재구성이 흔들립니다.
- 다중 고도 + 근접 패스를 추가해 같은 면을 여러 거리에서 확보
- 그래도 남는 반사 스트릭은 **뷰어에서 해당 각도를 제한**해 회피 (이 데모가 쓰는 방법)

## 2. 실내 촬영

| 공간 유형 | 방법 |
|---|---|
| 로비·아트리움 등 대공간 | 삼각대 격자 촬영 — 바닥에 격자를 잡고 지점마다 파노라마 |
| 오피스 기준층·객실 | 보행 캡처로 충분 (어안 또는 360 카메라) |
| 기계실·전기실 | 설비 정면 + 명판이 읽히는 근접 샷 별도 확보 |

**공통 수칙**
- 조명 고정 — 촬영 중 점등 상태를 바꾸지 않습니다
- 노출·화이트밸런스 수동 고정
- **루프 클로저 확보** — 시작 지점으로 반드시 되돌아와 같은 장면을 다시 찍습니다 (누적 오차 보정)
- 사람·이동 물체는 프레임에서 배제 (재구성 시 잔상으로 남음)

## 3. 스케일 기준물 — 계측 가능한 트윈의 전제

3DGS 결과물은 그 자체로 실제 치수를 모릅니다. 스케일을 주지 않으면 "보기 좋은 그림"에
그치고 **거리·면적을 잴 수 없습니다.**

- 최소: 1m 스케일바를 씬 안에 두고 여러 각도에서 촬영
- 권장: **RTK GCP 3점 이상** — 절대좌표까지 확보되어 도면·GIS와 정합 가능
- 확보 후 처리: 기준물 실측값 대비 재구성 결과의 비율로 similarity transform 산출 → 씬에 저장

> 이 단계를 건너뛰면 나중에 절대 복구할 수 없습니다. 재촬영 외에 방법이 없습니다.

## 4. 시공 중에만 찍을 수 있는 것

마감으로 덮이면 영원히 못 찍습니다. 해당 시점에 별도 촬영 일정을 잡아야 합니다.

- 천장 속 덕트·배관·케이블 트레이 (마감 직전)
- 벽체 매립 배관·전기 배선 (미장 직전)
- 기계실 바닥 앵커·기초

> 이 자료는 트윈 품질보다 **유지보수 시 "뜯기 전에 뭐가 있는지 아는 것"** 에 가치가 있습니다.

## 5. 설계·발주 사양서에 넣을 요구사항

준공 후 트윈-관제 연동이 가능하려면 **지금(설계 단계) 사양서에 박아야 하는 것들**입니다.
이 데모가 역으로 증명하는 지점이기도 합니다 — 최종 운영 화면을 먼저 만들어보면
무엇을 요구해야 하는지가 나옵니다.

| # | 요구사항 | 이유 |
|---|---|---|
| 1 | 설비 위치를 **좌표 메타데이터로 납품**(설비 ID + 층 + x,y,z 또는 실번호) | 트윈에 센서를 얹으려면 좌표가 필요. 준공 후 일일이 측량하면 비용이 몇 배 |
| 2 | 계통별 **통신 규격을 사양서에 명시**(BACnet/IP, Modbus TCP, OCPP, RTSP 등) | 규격이 안 정해진 채 시공되면 통합 단계에서 게이트웨이 비용 발생 |
| 3 | **포인트 리스트(BMS 태그) 표준 명명규칙** 사전 확정 | 벤더마다 다른 태그명이 오면 통합 화면에서 매핑 작업이 폭증 |
| 4 | 준공도서에 **as-built 도면 + 설비 사진** 포함 | 트윈과 대조할 기준이 됨 |
| 5 | 촬영을 위한 **공정 중 접근 일정**(§4 시점) | 마감 후에는 불가능 |
| 6 | 데이터 소유권·반출 조건 명시 | 벤더 종속(lock-in) 방지 |

## 6. 촬영 이후 파이프라인

```
촬영 이미지
   ↓ (포즈를 모르면) COLMAP SfM
   ↓ (포즈를 알면 — 이 데모처럼 렌더 기반이면 SfM 불필요)
3DGS 학습
   ↓
품질 진단 — held-out 시점 PSNR/SSIM, 스플랫 스케일 분포로 부유물 확인
   ↓
정제 — 공간 경계 크롭 / 스케일 기준 프루닝
   ↓
센서 좌표 배치 — 설계 좌표(§5-1)를 씬 좌표계로 변환해 앵커링
   ↓
관제 연동 — 계통별 어댑터 → 단일 상태 모델로 정규화 → 경보 시 SOP 연결
```

이 데모에서 실제로 수행한 구간은 **3DGS 학습 → 품질 진단 → 정제 → 센서 배치 → 관제 연동**
입니다. 촬영·SfM 구간은 공개 모델 렌더로 대체했습니다.

## 7. 규모 확장 시 비용 구조

한 공간에서 검증한 파이프라인을 건물 전체로 늘릴 때:

- **선형으로 늘어나는 것**: 촬영 시간, 학습 시간, 저장 용량, 센서 좌표 등록
- **거의 늘지 않는 것**: 관제 로직, SOP 체계, 어댑터 계층 (한 번 만들면 계통 수에 종속)
- **비선형으로 늘어나는 것**: 대규모 씬의 실시간 렌더 — 층·구역 단위로 씬을 쪼개고
  LOD·스트리밍을 도입해야 함 (단일 씬으로 초고층 전체를 올리는 방식은 성립하지 않음)

> 따라서 확장 전략은 "하나의 거대한 씬"이 아니라 **"구역 단위 씬 + 전환"** 입니다.
